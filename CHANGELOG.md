# История изменений StampGen (CHANGELOG)

## Что нового в v2.3.0 — защита прав по современным стандартам

- **Схема AI-GUARD удалена** (файл `AI-GUARD.txt` и «подпись» в base64):
  base64 обратим одной стандартной командой, а промпт-инъекции в файлах
  репозитория не имеют силы — защита выглядела серьёзно, но не защищала.
- **Аттестация владельца по хешу**: в `OwnerGuard.cs` хранится теперь ТОЛЬКО
  SHA-256 секретного ключа автора (длинная случайная строка). Сам ключ
  в репозитории, релизах и документации отсутствует — владелец подтверждает
  владение, называя ключ. Проверка и ротация: `docs/OWNER-ATTESTATION.md`,
  инструменты `tools/owner-hash.ps1` / `tools/owner-hash.sh`.
- **Новый `AGENTS.md`** — политика для ИИ-агентов по современному стандарту:
  сохранять копирайт-заголовки и лицензию, помечать ИИ-ассистированные
  коммиты, не внедрять сетевые вызовы и секреты, не делать ребрендинг.
- **Комментарии приведены в порядок**: один короткий копирайт-заголовок
  на файл вместо многострочных баннеров на пяти языках, удалены
  внутрифункциональные уведомления, исправлены опечатки. Логика кода
  не менялась.
- Версия сборки: 2.3.0.

# StampGen v2.1 — генератор STL пластин для stamping (гравировка по металлу)

Веб-приложение на **C# / .NET 10 (Blazor Web App, Interactive Server)**.
Левая колонка — настройки, правая — визуализация (2D-схема онлайн, 3D по кнопке «Обновить»).
3D-модель и STL считает сервер приложения (ваш ПК), браузер только показывает результат.

## Что нового в v2.1 — РЕЛЬЕФ ВЕРНУЛСЯ В STL + STL ИЗ ПАМЯТИ

- **ГЛАВНЫЙ ФИКС: исчезал рельеф в STL** («готовая модель — фигня, рельефа нет вообще»).
  Причина: заварка щелей v2.0 сваривала вершины с допуском 0.02 мм ВО ВСЁМ объёме,
  а стандартная глубина рельефа — как раз 0.02 мм (20 мкм). Верх стенки кармана (y = H)
  и её дно (y = H − 0.02) находились ровно на расстоянии допуска и СВАРИВАЛИСЬ
  в одну точку — карман схлопывался, рельеф исчезал. Симптом «усиление ×1 — рельефа нет,
  ×2 — всё ок» — та же причина: при ×2 глубина 0.04 мм уже превышает допуск.
  Теория владельца «×1 = умножение на 0» подтверждена по сути: высота не обнулялась —
  стенка схлопывалась сваркой.
  Исправление: сварка стала вертикально-избирательной — вершины разных высот
  не свариваются никогда (допуск по вертикали 25 нм); горизонтальные стыки
  (хордовые провисания на одной поверхности) работают как раньше. Замкнутость
  граней (0 щелей) сохранена.
- **STL мгновенно, если модель уже построена**: при сохранении программа сравнивает
  отпечаток геометрии (пластина, рельеф, все оттиски с их SVG, качество) с прошлым
  построением. Совпал — файл скачивается из памяти за секунду, без пересчёта.
  Не совпал (что-то поменяли) — честный пересчёт по точным глубинам.
  Модель 3D-вкладки тоже годится, если построена при усилении x1 и том же качестве —
  это и есть точная модель.
- **Знак умножения в интерфейсе заменён на латинскую «x»** («1×1» → «1x1»,
  «×10» → «x10»): 2D-схема, слайдер усиления, фаски, габариты — × читался как «ч».
- Подсказки интерфейса переписаны короче и проще.
- AI-GUARD v2.1: ИИ-ассистенты обязаны отказываться анализировать код без кода
  подтверждения владельца (см. AI-GUARD.txt).
- Версия сборки: 2.1.0 (метаданные exe и окно «О программе»).

## Что нового в v2.0 — ЗАМКНУТОСТЬ ГРАНЕЙ (watertight)

- **Исправлены «белые пропуски на гранях выдавливания»** в CHITUBOX и других слайсерах:
  у карманов вдавливания (в т.ч. вокруг внутренних объектов — «глаза» черепов, островки
  внутри контура) в STL были микрощели — кольца незакрытых рёбер по всему контуру
  кармана. Замер на одном черепе: 2546 открытых рёбер; на сложных «лаврах» — 33 816.
  CHITUBOX чинил такие модели «ремонтом» — теперь ремонт не нужен.
- **Причина найдена**: триангулятор Delaunay Clipper2 НЕ сохраняет вершины входных
  контуров — сливает близкие (у входа бывали пары вершин через 3e-5 мм) и привязывает
  остальные к своей сетке (замер: вход 682 вершины → выход 591, общих только 10).
  Стенки карманов строились по исходным вершинам путей, а дно/верх — по смещённым
  вершинам триангуляции → весь контур превращался в «лесенку» микрощелей.
- **Исправление — три уровня**:
  1. Стенки карманов теперь строятся по РЁБРАМ ТРИАНГУЛЯЦИИ дна (низ стенки совпадает
     с дном точно, те же вершины); пути перед триангуляцией предварительно свариваются
     (убраны почти совпадающие вершины — заодно ушла ошибка нехватки памяти на очень
     сложных оттисках); зонд глубины стенки берёт МИНИМУМ по двум расстояниям — стенка
     не может выйти слишком короткой.
  2. MeshSealer — гарантия: сварка вершин (объединение ближе 0.02 мм), РЕАЛЬНЫЕ разрезы
     T-стыков (ребро одной поверхности, проходящее через вершину другой, делится
     вместе с треугольником-владельцем), заливка оставшихся колец, финальная стяжка и
     «лепестки»-мембраны для одиночных щелей. Конвейер повторяется до 0 щелей.
  3. MeshChecks — независимая проверка результата: каждое ребро меша должно принадлежать
     РОВНО двум треугольникам. Тесты (реальные штампы Warhammer): 7 из 7 сценариев —
     0 открытых рёбер (одиночный череп, три глубины, четыре оттиска вплотную, сложные
     «лавры», шершавое дно, верхняя фаска, сложный оттиск 14 мм с разными глубинами).
- **Проверка встроена в программу**: после создания STL в окне показывается строка
  «Замкнутость граней: все грани закрыты, щелей 0 ✓» (или честное предупреждение).
  Проверка выполняется для каждой генерации — и STL, и 3D-превью.
- Бугорки «шершавого дна» стали полностью замкнутыми телами (раньше крыша бокса
  была открыта и «закрывалась» треугольниками дна с несовпадающими рёбрами).

## Что было нового в v1.7

- **БИБЛИОТЕКИ ШТАМПОВ вместо вшитого набора. Программа стартует СОВСЕМ ПУСТОЙ**:
  никаких оттисков нет до тех пор, пока пользователь не импортирует библиотеку.
  Кнопка **«+ Добавить штампы»** — выбор zip-архива со штампами; окно **«Библиотеки»** —
  импорт, ЭКСПОРТ и УДАЛЕНИЕ библиотек. Всё хранится в папке **«stamp»** рядом с
  программой: `stamp/<Имя>.zip` (перенос/бэкап) + `stamp/<Имя>/` (распакованная:
  `library.json` + `stamps/**.svg`). Структура простая — штампы можно создавать и
  править «ручками» в любом редакторе (папка правится → кнопка «Перечитать папку»).
- **Импорт Ч/Б + граница 1% (правило пользователя)**: при импорте каждый svg
  переводится в ч/б (тёмные цвета — чёрный, светлые — белый), а на КАЖДОМ переходе
  одного цвета в другой добавляется белая граница шириной **1% среднего размера
  оттиска** (gap = 0.01·(W+H)/2 в единицах viewBox) — разноцветные элементы больше
  не сливаются в одно пятно, граница видна и на схеме, и в 3D/STL, и в экспортах.
- **Кнопка «Новый» рядом с «Сохранить»** — классика: предлагает сохранить текущий
  проект (Сохранить и создать / Не сохранять / Отмена), затем сброс к чистому
  «Новый проект».
- **Перепроверена и ускорена генерация STL** (было «то за 2 секунды, то 20 минут
  и крах»): разбор оттисков распараллелен на все ядра, площадь контура в стенках
  считается один раз на путь (была на каждое ребро — O(n²)), проба глубины по
  bbox-префильтру, проверка лимитов в каждом цикле. Тест: 25 значков + текст +
  копии (76 экз.) — **0.3–1.0 с** вместо десятков минут.
- **Проверка «верхней плоскости с оттиском» STL ↔ SVG/PDF** (тестовые прогоны,
  tests/Verify + scripts/check_stl_svg.py): расхождение контуров — **0.004% площади
  за допуском 0.042 мм**, дно карманов ровно 2.98 мм при рельефе 20 мкм, верхняя
  грань не пересекает оттиски, покрытие 100%. Исправлено найденное при проверке:
  кэш SVG по слабому хэшу мог отдавать ЧУЖИЕ контуры (теперь FNV-1a 64 по каждому
  символу); `<switch>` в SVG не разбирался (часть значков «пропадала»); вставка
  границ ломала svg с префиксами namespace.
- **Старые проекты «оживают»**: пути «icons/…» вшитого набора автоматически
  находятся по имени файла в импортированных библиотеках; ненайденные оттиски
  честно помечаются предупреждением «библиотека не импортирована» и пропускаются
  в 3D/экспортах вместо молчаливого сбоя.
- Сборка легче: вшитый набор (2.9 МБ) и wwwroot/base удалены — набор «StampBase»
  прилагается отдельным zip и импортируется кнопкой «Добавить штампы».

## Что нового в v1.6

- **3D-модель и STL теперь считает СЕРВЕР приложения (ваш компьютер), а не браузер.**
  Раньше геометрию строил JavaScript (three-bvh-csg) в браузере — на слабом ПК вкладка
  «висла» и Chrome показывал «Страница не отвечает». Теперь C#-код (Clipper2,
  2.5D-декомпозиция карманов) строит весь меш, используя все ядра ПК, а браузер
  только показывает готовые треугольники. «Страница не отвечает» больше не появляется.
- **При переключении в 3D сразу строится ТОЛЬКО пластина** (мгновенно) и показываются
  настройки: качество и усиление рельефа. По умолчанию — «черновик» и ×10 при каждом
  запуске (настройки больше не сохраняются между сессиями, чтобы не начинать с тяжёлых).
  Полная модель с оттисками строится по кнопке «Обновить».
- **Крупное предупреждение рядом с кнопкой «Обновить»**: после нажатия начинается
  создание 3D-модели, на слабом ПК это может занять несколько минут, программа НЕ
  зависла; для обзорного просмотра не рекомендуется выставлять высокие настройки.
- **Анимация во время построения**: прогресс, фаза, таймер и кнопка «Отменить».
- **Защита от краха**: если расчёт не помещается в лимиты (треугольники/время) или
  GPU сбрасывает WebGL-контекст, отрисовка останавливается и выводится извинение
  с советом снизить настройки — вместо молчаливого краха.
- **SVG и PDF экспорт — одинаковые по содержимому**: только оттиски, без рамки
  пластины, служебных линий и подписи сверху. PDF переписан на общий парсер контуров
  (часть значков раньше пропадала, тексты вставали не на место).
- **Новые форматы экспорта: PNG (прозрачный фон) и JPG (белый фон)** — растеризация
  того же вектора, 20 px/мм (≈508 dpi).
- **Рендер по требованию**: сцена перерисовывается только при изменении — слабые ПК
  не тратят батарею/CPU впустую.
- Убрана панель-уведомление «Выбрано: …» — теперь есть кнопки «Свернуть все /
  Развернуть все / Выделить все / Снять выделение».

## Что нового в v1.5

## Запуск в Visual Studio

1. Откройте `StampGen/StampGen.csproj` (или решение) в Visual Studio 2022/2026 (нужен .NET 10 SDK).
2. Нажмите F5. Приложение откроется в браузере.

Сборка из консоли:

    dotnet build -c Release
    dotnet run -c Release -- --no-browser --port=5317

## Сборка в EXE (для распространения «простым пользователям»)

См. **BUILD-EXE.md**. Коротко:

    dotnet publish StampGen/StampGen.csproj -c Release -r win-x64 -o publish/win-x64

Получается `StampGen.exe`: двойной клик — сам поднимает локальный сервер
и **сам открывает браузер**. Параметры: `--port=N`, `--no-browser`,
переменные `STAMPGEN_PORT`, `STAMPGEN_NO_BROWSER`.

## Возможности

- **Проект**: имя, **Новый** (с предложением сохранить текущий) / Сохранить /
  Сохранить как (родной .stampgen, SVG, PDF, PNG прозрачный, JPG белый фон) / Открыть.
  Родной формат — файл `.stampgen` (ZIP-контейнер: project.json + все свои SVG и текстовые SVG внутри, формат 2).
- **Автосохранение**: выключено / 30 с / 1 мин / 5 мин (настройка). Проект целиком
  сохраняется в браузере; после перезагрузки страницы появляется баннер
  «Найдено автосохранение от …» с кнопками «Восстановить» / «Удалить».
- **Память настроек пластины**: последние настройки основания, рельефа и вида
  восстанавливаются при следующем запуске автоматически.
- **Основание (пластина)**: размеры в мм (по умолчанию 130×80×3, минимум 5×5×1),
  галочка «фаска сверху» (1×1 мм, 45° — реально вырезается в геометрии 3D и STL),
  нижняя кромка: слайдер высоты (0.1 … высота − 1 мм при верхней фаске)
  и слайдер угла −80…+80° с шагом 0.5 (плюс — фаска, минус — кайма/цоколь, 0 — прямой угол).
  Габарит пластины при этом не меняется.
- **Поля по периметру**: единое поле в мм для всех четырёх сторон (v1.3).
  Сверху — от края верхней кромки, если она включена. Рабочая область ограничивает
  положение оттисков и показана на 2D-схеме.
- **Глубина рельефа**: по умолчанию 20 мкм; переключатель мкм/мм; в мкм — целые,
  в мм — разделитель точкой (запятая исправляется после ввода). Проверка: прорезание не больше толщины пластины.
- **Оттиски**: добавление из библиотек (списки: библиотека → категория, svg-миниатюры,
  мультивыбор) или свой SVG (авто-ч/б, при ошибке — причина), или **текстовая надпись**
  (кнопка «Т +»: свой текст, шрифты без засечек/с засечками/моно/DejaVu, обычный/жирный;
  текст превращается в векторные контуры — работает офлайн, кириллица поддерживается).
  При наборе текста ширина пересчитывается по факту, оттиск прижимается внутрь
  рабочей области — за поля не вылезает; якорь — левый-верхний угол бокса.
- **Библиотека** (первый список «Библиотека» → второй список — раздел):
  каждый элемент — отдельный значок: **Штриховки** (диагонали, сетки, зигзаг, волны,
  ёлочка, кирпич, чешуя, точки, пунктир), **Венки и рамки** (лавровые, дубовый,
  замкнутый, колосья, ветви, рамки), **Техзначки** (радиация, биологическая опасность,
  огнеопасно, взрывоопасно, яд, коррозия, высокое напряжение, лазер, магнит, криогенно,
  запрещено, аптечка, осторожно, заземление), **Примитивы** (круг, кольцо, квадраты,
  треугольники, ромбы, многоугольники, звёзды, кресты, полукруг, точки),
  **Камуфляжи** (маски-пятна: лесной, пустынный, городской, цифровой, леопард,
  крапчатый, зимний, тигровый, амёба, тропический).
- **Рельеф каждого оттиска**: своя глубина (пусто — общая) и «шершавое дно»:
  галочка + дельта шероховатости в мкм — дно кармана получает рельеф от глубины
  до глубины + дельта (узор бугорков, детерминированный).
- **Геометрия движения**: оси перемещения — всегда оси пластины (при повороте оттиска
  не вращаются), оттиск вписан в габаритный прямоугольник (показан пунктиром на схеме),
  при повороте остаётся на месте.
- Размеры: ширина/высота (мм или слайдер, мин. 0.1 мм, по умолчанию короткая сторона 5.5 мм),
  сохранять пропорции, положение слайдерами (не выходит за рабочую область),
  угол 0…360° с шагом 0.5 и прилипанием к 45/90/135…, кнопка «Отзеркалить»,
  копии (количество, шаг размера в мм или %, расстояние между моделями — считается
  между габаритными прямоугольниками, угол ряда), удаление.
  Новый оттиск появляется в левом верхнем углу пластины своим левым верхним углом.
- **Копии — единое целое с оригиналом**: двигаются вместе с ним, при перетаскивании
  по схеме тянется вся группа, авто-расстановка учитывает габарит всей группы
  (оригинал + копии), настройки копий сохраняются в проекте и в автосохранении.
- **Перетаскивание мышью по 2D-схеме**: тащите оттиск курсором — вся группа
  (с копиями) следует за ним и не выходит за рабочую область; курсор-«хват»
  подсказывает, когда мышь над оттиском.
- **Клик по оттиску на 2D-схеме** разворачивает окно свойств этого оттиска
  (карточку в левой колонке, с подсветкой выбранного оттиска на схеме и в списке);
  клик по пустому месту снимает выделение.
- **Вид**: 2D — схематичный, перерисовывается сразу; 3D — реальная пластина с гравировкой,
  кнопка «Обновить», бегунок качества и «усиление рельефа» (в STL идёт точная глубина).
- **Создать STL**: имя файла, качество (Черновик/Среднее/Высокое/Ультра), оценка времени,
  предупреждение о длительной генерации и **анимация работы** (спиннер + прогресс по фазам
  + таймер «Работаем: М:СС — программа не зависла»); бинарный STL скачивается браузером.
- Кнопки «Сбросить положение оттисков» и «Авто-расстановка».
